What the administrator owns

Everything under ADMIN, and which parts need approval first.

The ADMIN menu

SectionHolds
Access ControlRoles and Users
FacilitiesHealth facilities and testing labs, and the Interface Tool connections
System ConfigurationGeneral Configuration, Instruments, Geographical Divisions, Implementation Partners, Funding Sources, Lab Storage
The module config sectionsThe dropdown lists on each module's request form. One section per module the installation runs

Two levels of administrator

LevelDoes
Lab administratorUsers, facilities, analyzers, module config lists, Interface Tool connections, audit trail lookups
National administratorAll of the above, plus roles and privileges, General Configuration, and Geographical Divisions
Get approval before changing these Sample ID format or prefix. Locking and expiry days. Same user can Review and Approve. Auto Approve Interface Results. Role privileges. Deleting a list entry. Renaming or removing a province or district. Each one applies across the whole installation at once, and setting it back does not undo its effect on the records already created.

Rules that hold everywhere

  • Never share a login. The activity log and the tester, reviewer, and approver names record whoever was signed in.
  • Set entries inactive. Never delete them.
  • Change one setting at a time, then check the effect.
  • Give each role the permissions its work needs and no more.

Job aid 2 of 5

Add a user, and set what they can reach

InteLIS has no self-registration. Every login is created here.

Add the user

ADMIN › Access Control › Users › Add User

  1. Enter the Full Name as it should appear on reports and in the activity log.
  2. Enter the email and phone number.
  3. Choose the Role. Permissions come from the role, never from the user.
  4. Set the Testing Lab. This scopes what the user sees to their own lab's work.
  5. Upload a Signature for anyone who approves results. 100 by 100 pixels.
  6. Set the Login ID and a starting password.
  7. Select Submit, then hand the Login ID and password to the user directly.
One login per person A shared login makes the activity log and the tester, reviewer, and approver names on every report worthless. To remove a departing user, edit the account and set it inactive. Never reuse the login for someone else. The old records stay attached to the old name.

Add or change a role

ADMIN › Access Control › Roles

FieldWhat to set
Role NameA name staff recognise, such as Lab Technician
Role CodeA short unique code
Landing PageThe page this role opens on. Data entry staff open straight onto the request form
Access TypeTesting Lab for lab staff. Collection Site for facility staff
PrivilegesTick each page the role can reach. Use the search box, do not scroll the list

To find which roles hold a given permission, use the Permission filter on the Roles page.

Never let one role both enter and approve Approval is the only check on result quality. A role holding both removes it.

Job aid 3 of 5

Add a facility, and connect an analyzer

Every sample is attached to a health facility and a testing lab.

Add a facility

ADMIN › Facilities › Add Facility

FieldWhat to enter
Facility NameThe name staff will search for
Facility CodeThe national unique code
Facility TypeHealth facility, or testing lab
Province/State, District/CountyThe location. Both must be set
Test TypeEvery test type the facility takes part in
Testing Point(s)The service points, such as VCT or PMTCT
Email(s), Report Email(s)Addresses for emailed results and report distribution
Test Type is what makes a facility appear A facility not ticked for a test type is missing from that test type's request form. A facility ticked for one test type stays missing from every other test type's form. This is the usual reason a facility is "missing".

For a testing lab, upload the signatories. They appear on the result PDFs that lab issues. To load many facilities at once, use Bulk Upload.

Add an analyzer

ADMIN › System Configuration › Instruments › Add Instrument

Enter the name, the test types it runs, and the configuration file that tells InteLIS how to read its result files. Without that file, results exported from the analyzer cannot be imported.

Connect the Interface Tool

ADMIN › Facilities › open the testing lab › Interface Tool Connections

  1. Select Generate Connection Code.
  2. Enter the three groups of the code, and the InteLIS URL shown above them, into the Interface Tool on the lab computer.
  3. Check the installation appears under Connected Installations with a recent Last Seen.
Code expiredGenerate another. Only one code can be outstanding at a time
Computer rebuiltUse Reconnect / Reinstall
Computer retired or lostUse Revoke. Other installations are unaffected

Keep the request form lists correct

Each module keeps its own lists. They do not share.

One config section per module

Config sectionLists it holds
VL ConfigSample Type, Rejection Reasons, Test Reasons, Results, ART Regimen, Test Failure Reasons, Recommended Corrective Actions
EID ConfigSample Type, Rejection Reasons, Test Reasons, Results
TB ConfigSample Type, Rejection Reasons, Test Reasons, Results
CD4 ConfigSample Type, Rejection Reasons, Test Reasons
Covid-19 ConfigSample Type, Rejection Reasons, Test Reasons, Results, Symptoms, Co-morbidities, Recommended Corrective Actions, QC Test Kits
Hepatitis ConfigSample Type, Rejection Reasons, Test Reasons, Results, Co-morbidities, Risk Factors
Other Lab Tests ConfigSample Types, Testing Reasons, Sample Rejection Reasons, Test Failure Reasons, Symptoms, Test Result Units, Test Methods, Test Categories, Test Type Configuration

Only the modules the installation runs appear in the ADMIN menu.

Adding to one module does not add to the others A sample type added under one module's config section does not appear on another module's request form. Add it under every module that needs it.

What each list controls

Sample TypeThe specimen types on the request form
Rejection ReasonsThe reasons offered when rejecting a sample
Test ReasonsThe indications for testing
ResultsThe result values for qualitative reporting
Test Failure ReasonsThe reasons offered when a test fails
Symptoms, Co-morbidities, Risk FactorsThe clinical checklists on the request form
ART RegimenThe regimen choices on the viral load request form
Recommended Corrective ActionsThe actions suggested on high viral load results
Retire, never delete To retire an entry, edit it and set the status to inactive. An inactive entry disappears from the form but stays readable on the records that already use it. Deleting it leaves those records unreadable. After adding an entry, open the request form and confirm it appears in its dropdown.

Geographical Divisions, Implementation Partners, Funding Sources, and Lab Storage are not module lists. They sit under ADMIN › System Configuration and serve every module.

Something is missing or wrong

The complaints an administrator actually receives, and what causes them.

Start here

ComplaintCause
A facility is missing from the request formThe facility is not ticked for that test type. Open it under Facilities and set Test Type
A district is missing from the request formIt was added without a parent province. Open Geographical Divisions and set the parent
An option is missing from a dropdownIt is inactive, or it was added under a different module's config section
A user sees the wrong menuThe role's privileges, not the user. Check under Access Control › Roles
A user sees another lab's samplesTesting Lab is not set on the user account
Results stopped arriving from the analyzerCheck Last Seen under Connected Installations, then Monitoring › Interface Machine Activity
A result was questionedMonitoring › Audit Trail. It shows which field changed, from what to what, by whom
A facility behaves oddly in report filtersSet Show Orphaned Facilities on the Facilities page. Its province or district is missing or wrongly linked

PageAnswers
