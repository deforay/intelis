InteLIS break-fix drills

Trainer sheet. Six drills, each one a real failure a lab has hit.

Before any drill

Where these may be run

Each drill damages a working installation on purpose.

Throwaway machines only A VM that can be reverted from a snapshot, or the container in dev/lab-vm, which runs systemd as PID 1 and so cannot be told apart from a lab machine by upgrade.sh. Never on titan, which real labs poll, and never on a lab's own machine.

The shape of every drill

  1. The trainee runs the drill's break command, or the trainer runs it while they look away.
  2. The trainee reproduces the symptom, so they see what a lab would report.
  3. The trainee diagnoses using only intelis, not guesswork.
  4. The trainee applies the fix and confirms the symptom is gone.
  5. Reset, and the next trainee gets the same machine in the same state.

Drill 1

The update refuses to finish

Cause: files the web server account cannot replace. The most common one in the field.

Break it

sudo chown -R root:root /var/www/intelis/var/cache

Symptom the trainee should see

Run intelis update. It gets as far as the composer step and fails there. The command-line tooling runs as www-data, which cannot replace cache files owned by root.

Diagnose

intelis check
ls -la /var/www/intelis/var/cache

The listing shows root root where every other directory in the installation shows the operator's account and www-data.

Fix

intelis provision

It hands ownership back and is safe to run repeatedly. Then re-run intelis update and let it finish.

The lesson worth stating out loud This state is usually self-inflicted, by running an intelis or composer command with sudo in front of it. That runs work as root which is supposed to run as the account InteLIS uses, and leaves behind exactly the files this drill creates. intelis asks for administrator rights itself, only for the steps that need them.

Drill 2

Permission denied

Cause: the access control lists on the installation directory were cleared.

Break it

sudo setfacl -R -b /var/www

Symptom the trainee should see

Uploads, exports and log writes start failing, and the message reaching the operator is some form of permission denied.

Fix

sudo setfacl -R -m u:$USER:rwx,u:www-data:rwx /var/www;

It grants read, write and execute to both the operator's account and the web server account, recursively.

Drill 3

The site will not open at all

Cause: the database server is not running. Carries the single most important diagnostic lesson on this sheet.

Break it

sudo systemctl stop mysql

Symptom the trainee should see

The browser shows an error rather than a login page. This is the call a lab actually makes, and they describe it as a symptom, not a cause.

Diagnose and fix

intelis fix-database

Or menu item 2, named for the symptom rather than the cause. It reports what it finds and asks before changing anything.

A stopped server has no /run/mysqld, and that is not a fault systemd creates that directory when MySQL starts and deletes it when MySQL stops. On a stopped server it is correctly absent. Recreating it by hand fixes nothing, and on a machine that later starts normally it leaves a directory with the wrong ownership behind. Start the service and look again before treating anything as damaged.

Reset

sudo systemctl start mysql

Drill 4

A collation mismatch

Cause: one table no longer matches the rest of the database.

Break it

sudo mysql vlsm -e "ALTER TABLE facility_details CONVERT TO CHARACTER SET utf8mb3 COLLATE utf8mb3_general_ci;"

Symptom the trainee should see

Pages and reports that join the altered table against another one fail with an illegal mix of collations, while the rest of the application carries on working. Partial breakage is what makes this one confusing in the field.

Fix

intelis db:collation

It sets every table and column back to one collation. The same repair exists in phpMyAdmin for Windows installations with no command line, under the database's Operations tab.

Drill 5

An update that was interrupted

Cause: power loss, a closed laptop lid, or an operator who pressed Ctrl-C.

Break it

Start an update and interrupt it once it is past the download and into the apply step.

intelis update
Ctrl-C

Fix

intelis update --rollback

The update takes a snapshot it can return to before it changes anything, and this puts the installation back to it.

Why this drill matters more than it looks An operator whose update was interrupted will assume the machine is ruined and start improvising. The one thing worth them remembering is that a rollback exists and is one command. Have every trainee run it once so it is familiar rather than theoretical.

Drill 6

Restore onto a different machine

Not a breakage. The exercise most often skipped, and the one that matters most.

Run it in pairs, across two machines

  1. On machine A, take a backup: intelis backup
  2. Confirm it reached its destination: intelis backup status
  3. Move to a partner's machine, or a fresh VM, and restore A's backup there: intelis restore
  4. Sign in to the restored installation and find a request that was registered on A.
Restoring onto a machine with nothing on it yet Do not install first and restore second. The restore prints the exact install command with the backup already attached, so the machine comes back with its data rather than empty.

What the drill is really teaching

A backup nobody has restoredis not a backup. This is the only exercise that proves the file is usable.
Restoring on the same machineproves less than it appears to. It can pass while depending on something only that machine has.
If a passphrase was setthe restore needs it, and it cannot be recovered from the backup file. A backup that cannot be decrypted is not a backup either.
